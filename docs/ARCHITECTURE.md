# 架构与模块边界

核心保存 [统一状态](../creative-core/state-schema.md)并选择技能；基础层定义结构、功能、衣物与动作语义；专项仅收窄命中的身体边界。写作模块决定场景与语言，视觉模块将同一事实转成可复制提示词，辅具模块约束设备能力。质检检查输出，标准库脚本检查仓库，二者不能互相替代。

用户当前明确修改优先；旧事实在未修改时继续有效。SCENE 随实际事件更新，不被“角色拥有假肢”这种长期能力覆盖。LOCKED 不是永不变化，训练、康复或明确改设定有依据时同步更新。未知事实不靠历史材料补齐；无关字段不必填。

现行 13 个目录与 ID 保持不变，不增加加载框架。核心与每个 SKILL.md 保持紧凑入口，例集与模板通过相对链接按需读取。单独安装需保留引用关系；只提供部分文件时应如实说明读取边界。

历史粗稿曾位于 release cleanup 前提交的 `archive/` 路径，2.2 收尾后已从 main 移除。来源与取舍记录保留在本文件和 `SOURCES-AND-DESIGN.md`，运行技能和校验均不依赖历史目录。旧资料有价值的方法在现行正文中重新表达，历史规则中的错误或矛盾只保留作来源语境。

验收区分结构、行为与产物：仓库脚本不评价文风；提示词自洽不能证明成图正确；教学改写对照不是独立盲测。实际模型对比应保存使用版本、输入、输出与评审理由。

写作要求集中在 writing-natural 的参考文件；日常、关系与故事的具体方法分别附在既有技能下，按任务触发读取，不新增平行技能体系。当前发布树本身不包含 `archive`；自检验证现行仓库可独立运行。
