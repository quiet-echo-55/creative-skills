# Creative Core

## 1. 任务

本 Skill 只做三件事：**锁状态、排优先级、选模块**。它不替用户决定角色应该有什么残疾，也不把身体差异转化成固定人格。

## 2. 两种规则不要混在一起

### 值与规则的关系

用户当前明确修改优先；未修改的既有事实继续有效。专项只解释身体结构边界，不覆盖本场已发生的穿脱、移动和设备损坏。新事件更新 SCENE，不无故改写 LOCKED；康复、训练或世界观事件确实改变长期能力时，记录变化原因后更新相应项。
用户给出的新设定如与旧设定冲突，明确是改设定还是叙事内变化；无法判断且影响成品时只问关键差异。行为库和题材惯例仅供选择。
身体检查决定可行性，写作技能决定如何表达，不能为了显示遵守规则把检查过程全写进正文。

### 通用不变量

`disability-foundation` 不负责用“常见情况”覆盖上述具体值，而是持续检查：

- 结构存在与功能能力是否被分开；
- 左右、残肢终点和保留关节是否连续；
- 衣物是否由真实身体/假肢正确支撑；
- 动作是否与支撑点、手占用和当前器械一致。

## 3. 两层状态

### LOCKED：跨场景保持

- `BODY_STATE.STRUCTURE`：天然结构存在/缺失、侧别、保留段、保留关节、终点；
- `BODY_STATE.FUNCTION`：主动运动、承重、抓握、活动范围等能力；
- `SENSATION_PROFILE`：只有已建立时才记录麻木、敏感、幻肢等；
- `VISION_BASELINE`：每只眼的结构存在与视觉能力分开；已设定的近视与矫正后能力也分别记录；
- `PROSTHESIS_CAPABILITIES`：器械能力边界；
- `WORLD_EXCEPTION`：魔法/科幻覆盖规则；
- `CHARACTER_PROFILE`：性格、偏好、隐私/帮助边界；
- `TASK_SKILLS`：按任务分项熟练度；
- `HABIT_PROFILE`：可选行为习惯；
- `VISUAL_INVARIANTS`：身体侧别、残肢终点、固定外貌等。

### SCENE：场景内可变化

- `PROSTHESIS_STATE`：worn / off_nearby / off_elsewhere / damaged / maintenance；
- `AID_STATE`：器械及眼镜是否在用、由谁持有、放在哪里；
- `MOBILITY_MODE`；
- `SUPPORT_POINTS`；
- `HAND_OCCUPANCY`；
- `CLOTHING_STATE`；
- `POSITION_STATE`；
- `ENVIRONMENT_STATE`；
- `FATIGUE_OR_DISCOMFORT`。

状态变化必须有足以理解的物理桥梁，可在前后文交代或合理省略日常步骤。脱假肢、拿拐杖、转移到轮椅、换衣服、摘下义眼都不是无过程变量跳转。

## 4. 不自动推断

除非用户给出或上下文已建立，不自动决定：

- 一个“不能用”的肢体就是缺失；
- 一只“失明”的眼睛就是眼球缺失；
- 截肢/肢体差异的精确层级；
- 残肢长度、疤痕、疼痛、幻肢；
- 是否喜欢/排斥假肢；
- 是否擅长单腿跳、爬行或轮椅；
- 是否会自嘲；
- 是否介意帮助、注视或触碰；
- 是否把空袖/空裤腿/空袜筒展示出来；
- 原因、年限、创伤程度或诊断名称。

## 5. 路由

- 任意身体结构/功能、残肢、服装拓扑或非标准移动 → `disability-foundation`
- 正式小说正文、续写、对白与去 AI 化 → `writing-natural`
- 身体动作、日常、跳/爬/转移、疲劳 → `writing-physicality`
- 人格、关系、帮助边界、凝视、恋爱、群像 → `writing-character`
- 开篇、悬念、信息释放、世界观、战斗、权力戏 → `writing-story`
- 人设图、插画、漫画、提示词 → `visual-continuity`
- 拐杖/轮椅/助行器/假肢/义手/义眼作为工具 → `assistive-devices`
- 经股截肢 → `amputation-transfemoral`
- 经肱截肢 → `amputation-transhumeral`
- 上下肢组合缺失 → `combined-limb-loss`
- 眼球缺失/义眼，或需要区分“眼球仍在但失明” → `ocular-loss`
- 输出前 → `quality-audit`

## 6. 核心纪律

- 身体结构和身体功能不互相偷换；
- 不把身体差异当人格快捷键；
- 不把每个动作都写成困难展览；
- 不把熟练写成“没有物理约束”；
- 不把器械写成无条件能力升级；
- 不因镜像构图交换角色自身左右；
- 不用解释性旁白重复已经被动作证明的事实。

历史粗稿已在 2.2 收尾后从 main 移除；现行技能是提炼后的独立交付，必要方法必须完整写入现行模块，不以“回 archive 查看”为执行步骤。只加载当前任务命中的现行模块，不把历史来源当运行规则；入口与引用不能访问时说明缺项，不声称已读取。用户仅要修改一个句子时无需展开全部状态。

正式小说正文默认叠加 `writing-natural`；其他模块负责领域逻辑，Natural 负责让这些事实自然进入文本。

## 7. 输出方式

用户只要成品时，状态卡在内部使用，不必全部展示。只有角色设定整理、连续性审计或用户要求时才显式输出状态表。
